# 컴포넌트 갤러리 화면(dev) 구현 로드맵

## 목적
- 개발자가 `src/components/`에 만든 공통 컴포넌트를 실기기/시뮬레이터에서 한 화면에 모아 눈으로 확인
- 앱 사용자 대상 화면 아님, 개발 전용

## 원칙
- Storybook 등 별도 도구 도입 안 함 — Expo Router 화면 하나로 충분 (YAGNI)
- 새 토큰/스타일 만들지 않음, 기존 컴포넌트를 있는 그대로 렌더링만
- 예쁘게 꾸미지 않음, 컴포넌트명 + variant 라벨로만 구분

## 1. 라우트 추가
- `app/dev/` 디렉토리 신설, `app/dev/index.tsx` 추가
- `(auth)`/`(main)` 그룹과 무관한 최상위 라우트 → URL `/dev`
- `app/_layout.tsx`의 `<Stack />`이 하위 라우트를 자동 인식하므로 등록 코드 불필요

## 2. 화면 컴포넌트
- `app/dev/_ComponentGalleryScreen.tsx` (컨벤션: 화면이름Screen.tsx)
- `app/dev/index.tsx`는 이 컴포넌트를 렌더링만 하는 얇은 진입점
- **주의:** Expo Router는 `app/` 밑의 모든 `.tsx`를 라우트로 인식 → 라우트가 아닌 화면 컴포넌트 파일은 `_` 프리픽스로 무시시켜야 함(안 하면 "missing default export" 경고 + 불필요한 라우트 생성). `app/` 안에 화면 컴포넌트를 분리할 때는 항상 `_`로 시작.

## 3. 표시 대상 — `src/components` 전수
현재 존재하는 컴포넌트 전부, 실제 props 타입 기준으로 variant 나열(임의 추가 금지):
- **Text** — 지원하는 fontSize/fontFamily variant 조합
- **Button** — `variant`(primary/secondary) × `disabled` 여부
- **Input** — `label`/`required`/`error`/`leftIcon` 조합 예시
- **Card** — `radius`(lg/xl)
- **Avatar** — `size`(sm/lg)
- **(layout) Header, BottomNav** — 로컬 `useState`로 `active` 등 필수 prop 목업 넘겨서 렌더 (둘 다 외부 네비게이션 컨텍스트 의존 없이 순수 props로 동작 확인됨)

## 4. 레이아웃
- `ScrollView` 하나에 컴포넌트별 섹션(제목 + variant 나열)을 세로로 쌓는 가장 단순한 구조
- 그리드/카드 UI 없음

## 5. 검증
- `tsc --noEmit` 통과
- 실기기/시뮬레이터에서 `/dev` 진입 후 스크롤하며 깨진 렌더 없는지 육안 확인

## 6. 컴포넌트 추가될 때마다
- 별도 로드맵 갱신 없이 갤러리 화면에 섹션만 추가 (신규 컴포넌트 구현 시 같이 반영 권장)

## Skip
- Storybook / 별도 디자인 시스템 문서화 툴 — 화면 하나로 충분한 규모, 컴포넌트 수가 많이 늘어나면 그때 재검토
- 프로덕션 빌드에서 `/dev` 라우트 숨기기(환경변수 분기 등) — 지금 요청 범위 밖, 배포 단계(Phase 8) 임박 시 필요하면 얘기해달라
