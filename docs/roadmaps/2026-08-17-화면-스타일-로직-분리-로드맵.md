# 화면 파일 내 스타일/로직 분리 로드맵

## 배경

현재 화면 파일(`app/**`)은 JSX 안에 className 문자열이 그대로 흩어져 있고, 조건부 스타일은 템플릿 리터럴로 상태/로직과 뒤섞여 있다.

예: [signup-basic-info.tsx:88-90](app/(auth)/signup-basic-info.tsx#L88-L90)
```
className={`flex-row items-center rounded-lg border-2 bg-white p-17 ${
  selected ? 'border-primary' : 'border-border-strong'
}`}
```

반면 공통 컴포넌트(`src/components/Button.tsx`)는 이미 `tailwind-variants`(`tv`)로 파일 상단에 스타일을 모아두고, JSX는 `button({ variant, disabled })` 형태로 참조만 한다. 이 패턴을 화면 파일에도 그대로 적용하면 된다.

## 방향

- **파일 분리 아님.** 한 파일 안에서 "스타일 정의 구획"과 "로직/마크업 구획"만 나눈다.
- 이미 설치된 `tailwind-variants`를 그대로 사용 (신규 의존성 추가 없음).
- 파일 상단(imports 다음, 컴포넌트 함수 앞)에 그 화면에서 쓰는 className을 `tv()` 또는 상수로 모아 정의.
- 컴포넌트 함수 내부 JSX는 정의된 스타일을 참조만 하고, 원시 className 문자열·조건부 템플릿 리터럴을 남기지 않는다.

## 단계

1. **컨벤션 검증 (파일럿 1개 화면)**
   - 대상: [signup-basic-info.tsx](app/(auth)/signup-basic-info.tsx) — 조건부 className이 많아 패턴 검증에 적합.
   - 상단에 `tv()` 스타일 구획을 만들고 JSX를 치환해본 뒤 사용자 리뷰 → 네이밍/구획 방식 확정.
2. **컨벤션을 CLAUDE.md 코딩 컨벤션 섹션에 반영**
   - 확정된 패턴(구획 위치, 네이밍 규칙)을 문서화해서 이후 신규 화면 작업에도 자동 적용되게 함.
3. **기존 화면에 그룹별 순차 적용** (화면 하나씩 완결 단위 원칙 유지, 한 요청에 한 그룹씩)
   - 로그인 4개 / 회원가입 13개 / 공지사항 4개 / 커뮤니티 3개 / 클럽 6개 / 정보 3개 / 알림 2개 / 마이페이지 8개
   - 공통 컴포넌트(`src/components/*`, `layout/*`)는 이미 동일 패턴 적용돼 있어 대상에서 제외.

## 범위 밖

- 파일을 스타일/로직 두 파일로 쪼개는 것 (요청대로 한 파일 내 구획만)
- 디자인 토큰(컬러/스페이싱) 값 변경
- 상태관리·API 연동 등 로직 자체의 리팩토링 — 스타일 코드 위치 이동만
