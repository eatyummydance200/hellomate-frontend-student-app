# Safe Area 적용 로드맵

## 배경

`Header`(`src/components/layout/Header.tsx`)는 `py-20` 고정 padding, `BottomNav`(`src/components/layout/BottomNav.tsx`)는 `pb-20` 고정 padding을 쓰고 있어 상태바/노치/홈 인디케이터 영역을 고려하지 않는다. `app/_layout.tsx`에도 `SafeAreaProvider`가 없다. `react-native-safe-area-context`(~5.6.0)는 `package.json`에 이미 설치돼 있지만 코드 어디서도 아직 쓰이지 않는 상태.

화면 레벨에서도 43개 파일이 `pt-`/`pb-` 고정값으로 여백을 잡고 있어, safe area 미반영이 Header/BottomNav 두 곳만의 문제가 아니라 전 화면에 걸쳐 있다.

## 방향: 신규 라이브러리 없이 기설치된 safe-area-context로 처리

- 새 의존성 추가 없음. 이미 설치된 `react-native-safe-area-context`를 표준 방식(`SafeAreaProvider` + `useSafeAreaInsets`)대로 적용한다.
- 대부분의 화면은 Header(상단)와 BottomNav(하단)로 감싸여 있으므로, 이 두 공통 컴포넌트에서 inset을 흡수하면 개별 화면 43개를 전부 고칠 필요는 없다.
- Header/BottomNav가 없는 화면(인증 플로우, 일부 모달형 서브 화면)만 개별 확인이 필요하다.

## 작업 단계

1. `app/_layout.tsx` — 최상위 `Stack`을 `SafeAreaProvider`로 감싸기
2. `Header.tsx` — `useSafeAreaInsets()`로 상단 inset을 기존 `py-20`에 더해 반영
3. `BottomNav.tsx` — 하단 inset을 기존 `pb-20`에 더해 반영
4. Header/BottomNav가 없는 화면 전수 확인
   - `(auth)` 그룹 (로그인/회원가입 13종): 자체 상단 여백 확인, 없으면 개별 적용
   - 헤더 없는 서브 화면(`club/chat`, `mypage/edit` 등): 필요 시 개별 적용
5. 탭 5개 화면 + `(auth)` 화면을 시뮬레이터(노치 기기)에서 겹침 여부 확인
6. 작업 후 `docs/reports/`에 보고서 작성, 커밋 메시지 추천

## 범위 밖

- 가로모드(landscape) safe area 대응 — `app.json`에 `orientation: "portrait"`로 고정돼 있어 세로 기준 insets(top/bottom)만 다룬다. 좌우(left/right) inset은 처리하지 않음
- Android edge-to-edge 제스처 네비게이션 별도 최적화 (우선 iOS 노치/상태바 기준)
- 기존 `pt-20`/`pb-20` 등 디자인 수치 자체 변경 — inset을 더하는 방식으로만 처리, 기존 여백 값은 유지
