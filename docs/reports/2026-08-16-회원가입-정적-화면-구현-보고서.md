## 화면 통합 판단

- **전공검색_검색결과있음/없음** → 검색어에 따른 같은 화면의 결과 유무 state라 클라이언트 필터링(`useState` + `.filter`)으로 하나의 화면에 통합했다.
- **이메일인증_인증번호입력/오답** → OTP 6칸 입력에 정답/오답 state만 다른 프레임이라, 더미 정답 코드(`123456`)와 실제 비교하는 로직으로 하나의 화면에 통합했다(기존 마이페이지·로그인 배치의 OTP 패턴과 동일한 판단).
- **서류인증_홈/사진업로드** → 업로드 전/후 state 차이라 `useState` 토글(빈 상태 ↔ 업로드된 목업 사진 + 다시촬영/삭제 버튼)로 하나의 화면에 통합했다.
- **서류 인증 진행중/완료/실패**는 세 프레임 모두 별도 화면으로 유지했다 — 실제로는 서류 검토(1~2일 소요)가 끝난 뒤 푸시 알림으로 결과를 통보하는 비동기 플로우라 같은 화면의 state 전환이 아니라 서로 다른 시점에 진입하는 별개 화면이기 때문이다. Phase 4라 실제 비동기 로직은 없으므로, "검토중" 화면의 확인 버튼은 골든 패스인 "완료" 화면으로 연결했고, "실패" 화면은 빌드는 됐지만 자동 연결된 트리거는 없다(실제로는 푸시 알림 딥링크로 진입하는 화면).

## 화면별 구현 내용

### 1~3. 기본 정보 입력 3단계 (`signup.tsx`, `signup-basic-info.tsx`, `signup-school-info.tsx`)

- 상단 진행률 바("N / 3" + 채워지는 바)로 3단계 폼을 구성, `router.push`로 순서대로 연결
- 1단계: 이름/이메일/아이디(중복확인 버튼 클릭 시 성공 메시지 토글)/비밀번호·비밀번호 확인(눈 아이콘 토글, 8자 이상·영문숫자포함·일치여부를 실시간 `useState` 검증으로 표시). 아이디/비밀번호는 Figma 목업이 이미 유효한 더미 값(`hellomate_student`/`pa1234`)으로 채워진 상태를 보여주고 있어 초기값으로 그대로 반영
- 2단계: 국적/사용 언어(탭할 때마다 더미 목록을 순환 선택, 실제 피커 라이브러리는 Phase 4라 추가하지 않음), 학생 유형 라디오 3종, 출생연도 선택
- 3단계: 전공 필드(탭 시 전공 검색 화면으로 이동), 학년 버튼 그룹 6종, 약관 동의 체크박스(전체동의 토글 포함) — "서비스 이용약관 동의"·"개인정보 수집 동의" 둘 다 체크해야 "인증하기" 버튼이 활성화됨

### 4. 전공 검색 (`signup-major-search.tsx`)

- 헤더 + 검색창 + 결과 리스트, 검색어로 더미 전공 10종을 클라이언트 필터링
- 결과가 없으면 빈 상태 아이콘 + 안내 문구로 전환
- "선택 완료" 클릭 시 `router.navigate`로 회원가입 3단계 화면에 파라미터(`major`)를 전달하며 복귀(스택에 중복 화면을 쌓지 않도록 `push` 대신 `navigate` 사용)

### 5. 서비스 이용약관 (`signup-terms.tsx`)

- 스크롤 가능한 약관 전문(목적/용어정의/게시와 개정/서비스 제공/이용계약 5개 조항) + 하단 고정 동의 체크박스 + 확인 버튼(체크해야 활성화)

### 6. 학생 인증 방법 선택 (`signup-verify.tsx`)

- 이메일 인증(가장 빠름 뱃지) / 서류 업로드 인증, 2개 카드로 분기

### 7~9. 이메일 인증 플로우 (`signup-verify-email*.tsx`)

- 이메일 입력 → 인증번호 6칸 입력(카운트다운, 재발송, 더미 정답 코드와 다르면 빨간 오류 상태로 전환) → 완료 화면(로그인 화면으로 `router.replace`)

### 10~13. 서류 인증 플로우 (`signup-verify-document*.tsx`)

- 서류 업로드(빈 상태 ↔ 목업 사진 업로드 상태 토글) → 검토중(진행 타임라인 표시) → 완료/실패(둘 다 별도 화면으로 빌드, 골든 패스는 완료로 연결)

## 토큰 결정

새로 등장한 색상은 대부분 기존 토큰과 일치했다: `primary`(`#006b55`), `primary.light`(`#49c9a7`), `border.strong`, `background.subtle`, `danger`. 일치하지 않는 값(아이디 중복확인 버튼 `#d5d7ff`/`#5a5c7f`, 보조 텍스트 `#595c7e`/`#575858`, 인증실패 경고 배경 `rgba(241,160,82,0.1)`)은 [[project_notice_screens]] 방침대로 인라인 임의값으로 처리했다. `tailwind.config.js`는 건드리지 않았다.

## 검증

- `npx tsc --noEmit` 통과 — 이전 배치들과 동일한 Expo Router 타입 캐시 이슈가 재발해, 사용자의 dev 서버는 건드리지 않고 별도 포트(8199)로 임시 서버를 띄워 새 라우트 13개를 전부 curl로 방문시켜 타입을 갱신한 뒤 종료했다
- `npx expo lint` 통과(경고 없음)
- 헤드리스 브라우저가 없어 같은 임시 서버로 13개 라우트 전부 `curl` 확인: `/(auth)/signup`, `/(auth)/signup-basic-info`, `/(auth)/signup-school-info`, `/(auth)/signup-major-search`, `/(auth)/signup-terms`, `/(auth)/signup-verify`, `/(auth)/signup-verify-email`, `/(auth)/signup-verify-email-code`, `/(auth)/signup-verify-email-done`, `/(auth)/signup-verify-document`, `/(auth)/signup-verify-document-pending`, `/(auth)/signup-verify-document-done`, `/(auth)/signup-verify-document-failed` — 전부 HTTP 200과 함께 각 화면의 핵심 한글 문구(예: "로그인에 사용할 정보를", "서류를 다시 확인해 주세요")가 렌더링된 HTML로 확인됨
