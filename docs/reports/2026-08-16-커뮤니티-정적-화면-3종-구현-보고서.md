# 커뮤니티 정적 화면 3종 구현 보고서

## 배경

Phase 4(정적 화면 퍼블리싱) 두 번째 배치로, Figma `hellomate-workspace` 파일의 커뮤니티 화면 그룹(노드 `53:219`) 3종을 API 연동 없이 더미 데이터로 하드코딩 구현했다. `53:219`는 하나의 링크에 커뮤니티 홈/게시글 상세/새 글 작성 3개 화면이 묶여 있어, 사용자에게 한 번에 3개를 만들지 확인받은 뒤 [[project_notice_screens]]와 동일하게 관련 플로우로 묶어 진행했다. [[project_notice_screens]]와 마찬가지로 반복 요소(카드, 댓글, 데이터 배열)는 별도 컴포넌트로 뽑지 않고 각 화면 파일 안에 그대로 중복 작성했다.

대상 화면 3종과 Figma 노드:

## 라우팅 구조

`app/community/_layout.tsx`를 새로 만들어 중첩 Stack을 구성했다(전부 `headerShown: false`, 화면마다 자체 헤더를 그림).

- 탭 화면인 `app/(tabs)/community.tsx`는 URL `/community`를, 새로 만든 `app/community/[id].tsx`·`write.tsx`는 각각 `/community/:id`·`/community/write`를 차지한다. 같은 접두사를 쓰지만 Expo Router가 정확 경로(`/community`)와 하위 경로(`/community/xxx`)를 구분해 처리하는 것을 `curl`로 직접 확인했다(아래 검증 항목 참고).
- `write` 화면의 "게시하기" 버튼은 실제 저장 로직 없이 `router.back()`으로 홈으로 복귀만 시킨다.
- 상세 화면(`[id].tsx`)은 `[id]` 공지사항 상세와 동일하게 `id` 파라미터를 실제로 사용하지 않고 Figma 시안(게시글 상세에 나온 특정 게시글) 내용을 고정 출력한다.

## 아키텍처: 기존 공통 컴포넌트/자산 재사용

- 커뮤니티 홈은 기존 `Header`/`BottomNav`를 그대로 재사용(공지사항 홈과 동일 패턴). 이번 배치로 커뮤니티 탭도 자체 Header/BottomNav를 갖추게 되어, [[project_notice_screens]]에서 남겼던 "탭 4개가 네비게이션 없는 과도기 상태" 문제가 하나 더 해소됐다(정보/클럽/마이페이지는 아직 미해결).
- 게시글 카드의 아바타는 Figma 상 외곽선 스타일 아이콘이라 기존 `Avatar` 컴포넌트(채워진 원 배경)와 시각적으로 달라, 새 아이콘 에셋(`icon-avatar-community.svg`)을 받아 그대로 썼다. 전송 버튼 아이콘은 기존 `icon-send.svg`(공지사항 담당자 문의 화면에서 이미 사용 중, 크기 16×9로 동일)를 그대로 재사용해 새로 받지 않았다.

## 화면별 구현 내용

### 1. 커뮤니티 홈 (`app/(tabs)/community.tsx`)

- "자유게시판" 타이틀 + 검색창(UI만) + "최신순" 정렬 표시(장식용, 클릭 로직 없음) + 게시글 카드 3건
- 각 카드: 작성자/언어/작성 시간 + 번역·원본 보기 라벨(정적 텍스트, 토글 로직 없음) + 본문 + 좋아요/댓글 수
- 카드 클릭 시 `router.push({ pathname: '/community/[id]', params: { id } })`로 상세 이동
- 우측 하단에 Figma 시안대로 떠 있는 원형 글쓰기 FAB 버튼 → `/community/write`로 이동

### 2. 게시글 상세 (`app/community/[id].tsx`)

- 자체 뒤로가기 헤더("게시글") + 원글 카드(좋아요/댓글 수) + "댓글 N" 섹션
- 댓글 2건 중 1건은 답글(재귀 아님, 1단 depth만) 딸린 구조를 배열로 하드코딩해 표현 — 답글은 배경색을 옅게(`background.muted`) 하고 좌측에 답글 화살표 아이콘을 붙여 구분
- 하단 고정 댓글 입력 바(공지사항 담당자 문의 화면과 동일하게 UI만, 전송 로직 없음)

### 3. 새 글 작성 (`app/community/write.tsx`)

- 뒤로가기 + 중앙 정렬 타이틀("새 글 작성") 헤더 — 기존 좌측 정렬 헤더 패턴과 달리 Figma가 타이틀을 화면 중앙에 배치해서, 뒤로가기 버튼은 그대로 두고 타이틀만 `absolute` + `text-center`로 겹쳐 중앙 정렬했다
- AI 번역 안내 배너 + "실명" 배지 + 제목/내용 입력 필드(둘 다 필수 표시 `*`) 카드
- 기존 `Input` 공통 컴포넌트를 쓰지 않고 필드를 직접 그렸다: Figma 라벨 폰트가 17px(`title` 토큰)인데 `Input` 컴포넌트는 라벨을 14px(`label` 토큰)로 고정하고 있어, 공통 컴포넌트를 건드리지 않고 화면에서 박스 스타일만 동일하게 재현하는 쪽을 택함(Phase 4 방침과 동일)
- 하단 고정 "게시하기" 버튼, 클릭 시 저장 없이 `router.back()`

## 에셋

Figma MCP 에셋 URL에서 아이콘 7종을 새로 받아 `assets/icons/`에 커밋했다: `icon-heart-outline`, `icon-heart-filled`(원글 좋아요는 채워진 빨간 하트, 목록/댓글 좋아요는 외곽선 하트로 Figma 시안에 실제로 다른 자산이 쓰여 있어 그대로 구분), `icon-message-circle`, `icon-sort-chevron`, `icon-pencil`, `icon-reply-arrow`, `icon-avatar-community`.

## 토큰 결정

새로 등장한 색상 대부분이 기존 토큰과 정확히 일치했다(`text.DEFAULT #3d4944`, `text.strong #171d1a`, `text.muted #6d7a74`, `primary #006b55`, `primary.dark #00503f`, `primary.light #49c9a7`, `border.strong #bccac3`, `background.muted #e9efeb`, `danger #f30707`) — 이런 곳은 전부 토큰을 그대로 사용했다.

정확히 일치하지 않는 값은 [[project_notice_screens]] 때 확정된 방침대로 `tailwind.config.js`를 건드리지 않고 화면 파일 안에서 인라인 임의값으로 처리했다: 헤더 타이틀 `#3d3d3d`, 댓글 입력 바의 "익명" 배지 배경 `#e3eae5`, 카드/텍스트 곳곳의 13/15/16px 등. 새로 토큰화가 필요할 만큼 반복되는 값은 없었다.

## 검증

- `npx tsc --noEmit` 통과
- `npx expo lint` 통과
- `npx expo start --web`으로 실제 구동
- 헤드리스 브라우저가 없어 `curl`로 3개 라우트 확인: `/community`(자유게시판/커뮤니티 텍스트 포함), `/community/p3`(게시글/댓글 텍스트 포함), `/community/write`(새 글 작성/게시하기 텍스트 포함) — 세 응답 모두 200이고 기대한 한글 텍스트가 SSR HTML에 실제로 렌더링되어 있음을 확인. 특히 `/community`와 `/community/[id]`가 URL 접두사를 공유함에도 서로 다른 화면이 정확히 응답하는 것을 확인해 라우트 충돌이 없음을 검증했다.
