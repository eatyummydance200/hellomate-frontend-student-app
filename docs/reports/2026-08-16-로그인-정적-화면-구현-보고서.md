# 로그인 정적 화면 구현 보고서

## 배경

Phase 4(정적 화면 퍼블리싱) 배치로, Figma `hellomate-workspace` 파일의 로그인 화면 그룹(노드 `61:3664`)에 속한 화면 전부를 API 연동 없이 더미 데이터로 하드코딩 구현했다. 그룹은 6개의 최상위 프레임을 담고 있었고, 그중 2쌍은 같은 화면의 서로 다른 state(정상/에러, 빈 값/채워진 값)라 인터랙티브한 하나의 화면으로 통합했다.

| Figma 프레임 | 실제 구현 | 구현 파일 |
| --- | --- | --- |
| 로그인_메인 (59:1902), 로그인_오류 (59:1960) | 로그인 화면 (1개 화면으로 통합) | `app/(auth)/index.tsx` |
| 비밀번호_인증 (59:2017) | 이메일 입력 | `app/(auth)/forgot-password.tsx` |
| 비밀번호_인증번호 (59:2041), 비밀번호_인증번호정답 (59:2075) | 인증번호 입력 (1개 화면으로 통합) | `app/(auth)/forgot-password-verify.tsx` |
| 새비밀번호_설정 (59:2115) | 새 비밀번호 설정 | `app/(auth)/forgot-password-new.tsx` |

## 화면 통합 판단

- **로그인_메인 / 로그인_오류** → 두 프레임은 같은 로그인 폼의 성공/실패 state 차이(아이디·비밀번호 필드 보더 색, 에러 메시지 노출 여부)일 뿐이라 별도 라우트로 만들지 않았다. 더미 아이디/비밀번호(`student123` / `hellomate123`)와 일치하면 `router.replace('/(tabs)')`, 다르면 에러 state를 `useState`로 켜는 방식으로 구현했다. [[project_club_screens]], [[project_mypage_screens]]에서 이미 반복된 "Figma 중복 프레임 = 같은 화면의 다른 state" 판단 기준을 그대로 따름.
- **비밀번호_인증번호 / 비밀번호_인증번호정답** → [[project_mypage_screens]]의 비밀번호 재설정 인증번호 화면과 동일한 패턴(빈 상태/채워진 상태)이라 같은 방식(6칸 자동 포커스 이동 입력 + `03:00` 카운트다운 + 재발송 시 초기화)으로 하나의 화면에 통합했다.
- 이 그룹에는 "완료" 프레임이 없어(마이페이지 비밀번호 재설정 플로우와 달리), 새 비밀번호 설정 화면의 "변경하기" 버튼은 로그인 화면으로 `router.replace('/(auth)')`한다.

## 화면별 구현 내용

### 1. 로그인 (`app/(auth)/index.tsx`)

- 기존 자리표시자(텍스트+링크만 있던 화면)를 실제 화면으로 교체
- 로고(HelloMate 아이콘+워드마크 세로 조합) + 슬로건, 아이디/비밀번호 입력 필드(비밀번호는 눈 아이콘으로 보기 전환), 자동 로그인 체크박스(`useState` 토글), 로그인 버튼, 하단 회원가입 유도 텍스트로 구성
- 로그인 버튼은 더미 계정과 일치할 때만 `/(tabs)`로 이동, 불일치 시 두 필드 보더가 `danger` 색으로 바뀌고 에러 메시지가 노출됨(로그인_오류 프레임 재현). 입력값을 다시 바꾸면 에러 state는 초기화됨
- "비밀번호 찾기" → `forgot-password`, "회원가입" → 기존 `(auth)/signup` 자리표시자로 연결

### 2. 비밀번호 찾기 - 이메일 입력 (`app/(auth)/forgot-password.tsx`)

- 자체 뒤로가기 헤더("비밀번호 찾기") + "비밀번호를 잊으셨나요?" 안내 문구 + 이메일 입력 필드
- [[project_mypage_screens]]의 `reset-password.tsx`와 레이아웃은 거의 동일하지만, 이 화면은 로그인 플로우용이라 상단 헤딩 문구가 하나 더 있고 헤더 타이틀도 다름(마이페이지판은 "비밀번호 재설정", 이쪽은 "비밀번호 찾기") — Figma 실측 기준으로 구분해서 각각 하드코딩
- "인증 번호 전송하기" → `forgot-password-verify`로 이동

### 3. 비밀번호 찾기 - 인증번호 입력 (`app/(auth)/forgot-password-verify.tsx`)

- 6칸 개별 입력(입력 시 다음 칸 자동 포커스), `03:00`부터 카운트다운 타이머, 재발송 시 초기화
- "다음" 버튼은 6자리를 모두 입력해야 활성화(비활성 시 `text-muted/50` 배경) → `forgot-password-new`로 이동

### 4. 비밀번호 찾기 - 새 비밀번호 설정 (`app/(auth)/forgot-password-new.tsx`)

- 새 비밀번호 / 비밀번호 확인 2개 필드, 각각 눈 아이콘으로 보기 전환
- "변경하기" → 완료 화면이 없는 그룹이라 로그인 화면으로 `router.replace('/(auth)')`

## 에셋

Figma MCP 에셋 URL에서 새로 받아 커밋한 것: 로고 조합 SVG(`assets/images/logo-lockup.svg`, 아이콘+워드마크 세로 배치, 기존 가로형 `logo.png`와 별개 에셋), 아이디 필드 사람 아이콘(`assets/icons/icon-user.svg`), 로그인 에러 상태 아이콘(`assets/icons/icon-alert-circle.svg`, 기존 `icon-info-circle*` 시리즈와 글리프가 달라 새로 받음). 비밀번호 필드 자물쇠(`icon-lock`), 눈 아이콘(`icon-eye-toggle`), 뒤로가기(`icon-chevron-left`), 이메일(`icon-mail`), 타이머(`icon-timer`), 다음 화살표(`icon-arrow-right-sm`), 체크(`icon-check`)는 [[project_mypage_screens]]·[[project_club_screens]] 배치에서 이미 받은 에셋을 글리프 기준으로 재사용했다.

## 토큰 결정

로그인 화면 버튼 색만 `#49c9a7`(`primary.light`)이고, 나머지 화면(비밀번호 찾기 플로우) 버튼은 `#006b55`(`primary`) — Figma 실측값 그대로 구분해서 적용했다. 에러 보더/텍스트는 [[project_common_components]]에서 이미 확정된 대로 Figma 원본 헥사(`#ba1a1a`/`#e56d6d`) 대신 `danger` 토큰으로 통일했다. 일치하지 않는 값(배경 `#f6f8f8`, 보조 텍스트 `#595c7e`)은 [[project_notice_screens]] 방침대로 인라인 임의값으로 처리했다. `tailwind.config.js`는 건드리지 않았다.

## 검증

- `npx tsc --noEmit` 통과 — [[project_mypage_screens]]에서 확인된 것과 같은 Expo Router 타입 캐시 이슈가 재발해, 사용자의 dev 서버는 건드리지 않고 별도 포트(8199)로 임시 서버를 띄워 타입만 갱신한 뒤 프로세스 종료까지 확인했다
- `npx expo lint` 통과(수정 필요한 경고 없음)
- 같은 임시 서버로 4개 라우트 전부 `curl` 확인: `/(auth)`, `/forgot-password`, `/forgot-password-verify`, `/forgot-password-new` — 전부 HTTP 200과 함께 화면별 핵심 한글 문구(예: "아이디를 입력하세요", "비밀번호를 잊으셨나요?", "인증 번호 재발송", "새 비밀번호 설정")가 렌더링된 HTML에 포함됨을 확인
- 로그인 성공/실패 분기(더미 계정 일치 여부에 따른 라우팅·에러 state)는 코드 로직으로 구현했으나, 실제 기기/시뮬레이터 조작 테스트는 이번 세션에서 수행하지 않음 — 다음에 `expo start`로 직접 눌러보는 확인 권장
