# 마이페이지 정적 화면 구현 보고서

## 배경

Phase 4(정적 화면 퍼블리싱) 여섯 번째 배치로, Figma `hellomate-workspace` 파일의 마이페이지 화면 그룹(노드 `58:223`)에 속한 화면 전부를 API 연동 없이 더미 데이터로 하드코딩 구현했다. 그룹은 9개의 최상위 프레임을 담고 있었고, 비밀번호 재설정 인증번호 입력 화면은 빈 상태(`24:3309`)와 값이 채워진 상태(`24:3343`)로 중복 존재해 하나의 인터랙티브 화면으로 통합했다.

| Figma 프레임 | 실제 구현 | 구현 파일 |
| --- | --- | --- |
| 마이페이지홈 (24:2976) | 탭 홈 화면 | `app/(tabs)/mypage.tsx` |
| 내정보 수정 (24:3041) | 폼 화면 | `app/mypage/edit.tsx` |
| 비밀번호 재설정_인증 (24:3132) | 이메일 입력 | `app/mypage/reset-password.tsx` |
| 비밀번호재설정_인증번호 (24:3309, 24:3343) | 인증번호 입력 (1개 화면으로 통합) | `app/mypage/reset-password-verify.tsx` |
| 비밀번호 재설정_설정 (24:3383) | 새 비밀번호 설정 | `app/mypage/reset-password-new.tsx` |

## 화면 통합 판단

- **비밀번호재설정_인증번호** → Figma에 빈 입력 상태와 6자리 모두 채워진 상태 두 프레임이 있었는데, 이는 같은 화면의 서로 다른 state일 뿐이라 별도 라우트로 만들지 않고 `useState` 기반 인터랙티브 입력(자동 포커스 이동, `03:00`부터 카운트다운, 재발송 시 초기화)으로 하나의 화면에 합쳤다.

## 화면별 구현 내용

### 1. 마이페이지홈 (`app/(tabs)/mypage.tsx`)

- 기존 자리표시자(텍스트+링크만 있던 화면)를 실제 화면으로 교체, 공통 `Header`·`BottomNav`·`Avatar`(lg) 적용 — 이번 배치로 마이페이지 탭도 [[project_info_screens]] 때와 같은 이유로 실제 네비게이션 쉘을 갖추게 됨(과도기 상태였던 마지막 탭 해소)
- "계정 관리"(내 정보 수정 / 이메일 인증 뱃지 / 비밀번호 재설정), "커뮤니티"(내가 작성한 글 / 내가 작성한 댓글), 로그아웃 3개 섹션을 `MENU_ROW` 배열로 렌더링, 각 행 클릭 시 해당 라우트로 이동
- 로그아웃은 Phase 4라 실제 세션 종료 없이 `router.replace('/(auth)')`만 수행

### 2. 내정보 수정 (`app/mypage/edit.tsx`)

- 자체 뒤로가기 헤더 + 이름 텍스트 입력, 국적/사용 언어/출생연도/전공 선택형 필드(Phase 4라 실제 피커 없이 자리표시자만 표시), 학생 유형 라디오 3종(`useState`로 선택 전환), 학년 버튼 그룹 6종(`useState`로 단일 선택)
- 하단 "수정하기" 버튼은 Phase 4라 실제 저장 없이 `router.back()`만 수행

### 3~6. 비밀번호 재설정 플로우 (`app/mypage/reset-password*.tsx`)

- 이메일 입력 → 인증번호 입력(6칸 개별 입력 + 카운트다운 + 재발송) → 새 비밀번호 설정(비밀번호/확인 2개 필드, 눈 아이콘으로 보기 전환) → 완료(성공 아이콘 + 안내 문구) 순서로 4개 화면을 `router.push`로 연결
- 완료 화면은 우측 상단 닫기 아이콘으로 `router.replace('/(tabs)/mypage')`, 마이페이지 홈으로 복귀
- 인증번호 "다음" 버튼은 6자리를 모두 입력해야 활성화(비활성 시 `text-muted/50` 배경)

### 7. 내가 작성한 글 (`app/mypage/posts.tsx`)

- 자체 뒤로가기 헤더 + 전체/커뮤니티/클럽 필터 탭(`useState`로 클라이언트 필터링)
- 카드 2종을 하나의 더미 배열(`POSTS`)에 유니온 타입으로 담고 `category`로 분기 렌더링: 커뮤니티형(좋아요/댓글 수), 클럽형(참여 인원 진행바 + 마감일)

### 8. 내가 작성한 댓글 (`app/mypage/comments.tsx`)

- 자체 뒤로가기 헤더 + 날짜별(오늘/어제) 그룹 렌더링, 각 댓글 카드에 원문 인용 박스(좌측 초록 보더 + 연한 배경) 포함
- 안읽음 표시로 보이는 초록 점은 Figma 카드 4개 중 2개에만 있어 `isNew` 옵셔널 플래그로 재현

## 에셋

Figma MCP 에셋 URL에서 아이콘 6종을 새로 받아 커밋했다: `icon-mail`, `icon-lock`, `icon-eye-toggle`, `icon-timer`, `icon-arrow-right-sm`, `icon-check-circle`(모두 `assets/icons/`). 뒤로가기 화살표(`icon-chevron-left`), 닫기(`icon-close`), 드롭다운 화살표(`icon-chevron-down`), 달력(`icon-calendar`, `icon-calendar-xs`), 검색(`icon-search`), 좋아요/댓글(`icon-heart-outline`, `icon-message-circle`)은 기존 아이콘을 글리프 기준으로 재사용했다.

## 토큰 결정

새로 등장한 색상은 대부분 기존 토큰과 일치했다: `primary`(`#006b55`), `primary.light`(`#49c9a7`, 완료 화면 성공 아이콘/인증됨 뱃지/댓글 인용 박스 보더), `danger`(`#f30707`→`#ba1a1a` 계열은 [[project_common_components]]에서 이미 `danger` 토큰으로 통일하기로 확정된 사안이라 로그아웃 텍스트에 그대로 적용). 일치하지 않는 값(본문 보조 텍스트 `#595c7e`, 완료 화면 배경 `#f6f8f8`, 카드 태그 뱃지 `#a4b3ff`/`#ffdad6`)은 [[project_notice_screens]] 방침대로 인라인 임의값으로 처리했다. `tailwind.config.js`는 건드리지 않았다.

## 검증

- `npx tsc --noEmit` 통과 — [[project_info_screens]]에서 확인된 것과 같은 Expo Router 타입 캐시 이슈가 재발해, 사용자의 8081 dev 서버는 건드리지 않고 별도 포트(8199)로 임시 서버를 띄워 타입만 갱신한 뒤 종료했다
- `npx expo lint` 통과(배열 타입 표기 경고 1건 발견 후 `T[]` 형태로 수정)
- 헤드리스 브라우저가 없어 같은 임시 서버로 8개 라우트 전부 `curl` 확인: `/mypage`, `/mypage/edit`, `/mypage/reset-password`, `/mypage/reset-password-verify`, `/mypage/reset-password-new`, `/mypage/reset-password-done`, `/mypage/posts`, `/mypage/comments` — 전부 HTTP 200과 함께 45~59KB의 정상 렌더링 HTML 확인(에러/빈 페이지 아님)
