# Safe Area 적용 보고서 (상단 전용)

## 배경

[[2026-08-17-safe-area-적용-로드맵]] 실행 중, 화면 34개에 개별로 inset 코드를 넣는 최초 방식 대신 더 적은 지점에서 공통 처리하는 방법을 논의했다. 결론은 이렇다.

- 루트(`app/_layout.tsx`)에서 `<Stack>`을 `SafeAreaView`로 한 번 감싸면 `push`로 쌓이는 일반 화면은 전부 자동 커버된다.
- 단, `presentation: 'modal'` / `transparentModal`로 등록된 화면은 네이티브에서 별도 화면으로 뜨기 때문에 부모의 padding이 물리적으로 닿지 않는다 — 이 화면들만은 개별 처리가 구조적으로 불가피하다.
- 이번 작업 범위는 **상단(상태바)만**으로 한정했다. 하단(홈 인디케이터)은 별도 논의 후 진행하기로 하고 이번엔 손대지 않았다.

## 적용한 변경

1. `app/_layout.tsx` — `<Stack>`을 `SafeAreaView edges={['top']}`로 감쌈. 탭 5개, `(auth)` 화면 전부, notice/club/community/info/mypage/notifications의 일반(push) 화면까지 전부 여기서 자동 처리됨
2. `src/components/layout/Header.tsx` — 루트에서 이미 top 여백을 확보하므로, 직전에 넣었던 개별 `useSafeAreaInsets()` top 처리를 제거하고 원래의 `py-20`으로 되돌림 (이중 적용 방지)
3. `src/components/layout/BottomNav.tsx` — 이번 범위가 상단 전용이라, 직전에 넣었던 개별 bottom inset 코드도 제거하고 원래의 `pb-20`으로 되돌림
4. `app/notice/contact.tsx` — `presentation: 'modal'`이라 루트 래퍼가 닿지 않음. 자체 헤더 행에 `useSafeAreaInsets()`로 top inset 개별 추가
5. `app/notifications/settings.tsx` — 위와 동일한 이유로 자체 헤더 행에 top inset 개별 추가

`club/joined.tsx`, `info/edit-request.tsx`는 `transparentModal` + 하단 시트(`justify-end`) 구조라 위쪽에 보이는 콘텐츠가 없어 이번 상단 작업 대상에서 제외했다.

## 처리 범위 요약

| 구분 | 파일 수 | 처리 방식 |
| --- | --- | --- |
| 일반(push) 화면 전체 | 30개 | 루트 1곳에서 자동 처리 (개별 수정 없음) |
| 풀스크린 모달 (`presentation: 'modal'`) | 2개 (`notice/contact`, `notifications/settings`) | 파일별 개별 처리 (네이티브 모달 구조상 불가피) |
| 바텀시트 모달 (`transparentModal`) | 2개 (`club/joined`, `info/edit-request`) | 상단 콘텐츠 없어 제외 |
