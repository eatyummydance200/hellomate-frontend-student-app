# 클럽 정적 화면 구현 보고서

## 배경

Phase 4(정적 화면 퍼블리싱) 세 번째 배치로, Figma `hellomate-workspace` 파일의 클럽 화면 그룹(노드 `54:220`)에 속한 화면 전부를 API 연동 없이 더미 데이터로 하드코딩 구현했다. `54:220`은 8개의 최상위 프레임을 담고 있었는데, 그중 "클럽 만들기"와 "클럽 단톡방"은 각각 2개씩 있었다 — 확인해보니 서로 다른 화면이 아니라 같은 화면의 빈 상태/채움 상태(클럽 만들기), 접힘/펼침 상태(클럽 단톡방 공지 배너)였다. 그래서 실제로 구현한 화면은 6개다.

| Figma 프레임 | 실제 구현 | 구현 파일 |
| --- | --- | --- |
| 클럽 홈 (24:608) + 내 클럽 홈 (24:757) | 탭 전환 1개 화면 | `app/(tabs)/club.tsx` |
| 클럽 상세글 (24:879) | 상세 화면 | `app/club/[id].tsx` |
| 클럽 만들기 (24:932 / 24:981) | 폼 화면 1개 | `app/club/create.tsx` |
| 클럽 가입완료 (24:1030) | 바텀시트 모달 | `app/club/joined.tsx` |
| 클럽 단톡방 (24:1411 / 24:1470) | 채팅방 화면 1개 | `app/club/chat.tsx` |

## 화면 통합 판단

Figma가 프레임을 나눈 방식과 실제 앱에서 화면을 나누는 방식이 항상 같지는 않았다. 각각 이유를 남긴다.

- **클럽 홈 / 내 클럽 홈** → Figma는 "전체 클럽"·"내 클럽" 탭 전환을 별도 프레임(별도 화면 이동)으로 그렸지만, 실제 앱에서 상단 탭 전환은 라우팅이 아니라 같은 화면 안의 로컬 상태(`useState`)로 구현하는 게 자연스러운 UX다. 두 프레임의 내용을 모두 `app/(tabs)/club.tsx` 하나에 넣고 탭 클릭으로 전환하도록 구현했다. (Figma가 시안 목적으로 화면을 나눠 그린 것이지, 실제 내비게이션 구조를 지시한 게 아니라고 판단)
- **클럽 만들기 (빈 상태 vs 채움 상태)** → 폼에 아무것도 안 쓴 상태와 예시 값이 채워진 상태 2개 프레임이 있었는데, 이는 하나의 폼 화면이 사용자 입력 전/후를 보여주는 것뿐이라 화면 1개로 구현. 빈 상태(24:932)를 기준으로 만들었다.
- **클럽 단톡방 (공지 배너 접힘 vs 펼침)** → "클럽 소개" 공지 배너가 접힌 상태와 펼쳐진 상태 2개 프레임이 있었는데, 실제로는 탭하면 펼쳐지는 아코디언 UI로 보여 `useState` 토글로 구현했다(펼쳤을 때 노출되는 공지 전문 텍스트는 펼침 프레임 24:1517에서 그대로 가져옴).
- **클럽 가입완료** → Figma 프레임을 열어보니 클럽 상세글 화면 위에 반투명 배경 + 하단 바텀시트가 얹힌 모달 목업이었다. `app/club/joined.tsx`를 `presentation: 'transparentModal'`로 등록해 바텀시트 스타일 오버레이로 구현했다(`app/club/_layout.tsx`에서 설정).

## 화면별 구현 내용

### 1. 클럽 홈 / 내 클럽 (`app/(tabs)/club.tsx`)

- 기존 공통 `Header`, `BottomNav` 재사용
- "전체 클럽" 탭: 클럽 개설 유도 히어로 배너(클릭 시 `/club/create`) + 검색창(UI만) + 정렬 표시(장식용) + 클럽 카드 4건. 카드는 상태별로 배지 색이 다르다 — 참여 가능(초록 배경), 참여 중(연한 초록), 마감(회색 + 카드 전체 `opacity-50`)
- "내 클럽" 탭: 가입한 클럽 수 배지 + 카드별 "채팅"(`/club/chat`)·"나가기" 버튼 + 하단에 점선 테두리 "더 많은 클럽을 찾고 싶나요?" 유도 카드(클릭 시 "전체 클럽" 탭으로 전환)
- 카드 클릭 시 두 탭 모두 `router.push({ pathname: '/club/[id]', params: { id } })`로 상세 이동

### 2. 클럽 상세글 (`app/club/[id].tsx`)

- 자체 뒤로가기 헤더 + 클럽 소개 카드(문단 2개 + 활동 목록) + 모집 현황 진행바 + 클럽장 정보(아바타 사진 + 이름/역할 + 채팅 버튼) + 하단 고정 "참여하기" CTA
- "참여하기" 클릭 시 `/club/joined` 모달로 이동
- `id` 파라미터는 [[project_notice_screens]]·[[project_community_screens]]와 동일하게 아직 미사용 — Figma 시안 내용을 고정 출력

### 3. 클럽 만들기 (`app/club/create.tsx`)

- 클럽 이름(텍스트 입력) / 최대 인원(`-`·`+` 스테퍼, 실제로 동작하는 로컬 상태, 1~99 범위) / 모집 마감일(달력 아이콘 + `mm/dd/yyyy` placeholder, 날짜 선택 라이브러리 없이 정적 표시) / 클럽 소개(textarea) 4개 필드
- "클럽 개설하기" 버튼은 [[project_community_screens]]의 "새 글 작성" 화면과 동일하게 저장 로직 없이 클럽 홈으로 이동만 시킨다(Figma의 비활성 회색 스타일 대신 항상 눌리는 primary 버튼으로 통일 — Phase 4 CTA 버튼들과 일관성 유지)

### 4. 클럽 가입완료 (`app/club/joined.tsx`)

- 반투명 배경(탭하면 뒤로가기) + 하단 바텀시트: 체크 아이콘 + "클럽에 참여했어요!" + "채팅방 입장하기" 버튼
- 버튼 클릭 시 `/club/chat`으로 `router.replace`(모달을 스택에 남기지 않고 채팅방으로 전환)

### 5. 클럽 단톡방 (`app/club/chat.tsx`)

- 배경색 `#eff5f1`(기존 `background.subtle` 토큰과 정확히 일치)
- 헤더(클럽명/멤버 수 + 닫기 버튼) + 탭하면 펼쳐지는 "클럽 소개" 공지 배너(화살표 아이콘 회전) + 시스템 메시지("OO님이 들어왔습니다") + 채팅 버블(상대는 좌측 흰 배경, 나는 우측 초록 배경 — 공지사항 담당자 문의 화면과 동일 패턴) + 하단 메시지 입력 바(UI만)

## 에셋

Figma MCP 에셋 URL에서 아이콘 9종 + 클럽장 프로필 사진 1종을 새로 받아 커밋했다: `icon-club-hero`, `icon-calendar`, `icon-chat-bubble`, `icon-minus`, `icon-plus`, `icon-compass`, `icon-check`, `icon-info-circle`, `icon-chevron-down`(`assets/icons/`), `club-host-avatar.png`(`assets/images/`). 닫기 아이콘은 기존 `icon-close.svg`(공지사항 담당자 문의 화면에서 이미 사용 중)를, 전송 아이콘은 기존 `icon-send.svg`를 그대로 재사용해 새로 받지 않았다.

## 토큰 결정

이번에도 새로 등장한 색상 다수가 기존 토큰과 정확히 일치했다: `primary`, `primary.dark`(`#00503f`), `primary.light`(`#49c9a7`), `text.strong`/`text.DEFAULT`/`text.muted`, `border.strong`(`#bccac3` — 카운터 버튼 테두리, 드래그 핸들, 카드 테두리 모두 정확히 일치), `background.muted`(`#e9efeb`), `background.subtle`(`#eff5f1` — 단톡방 배경). 나머지(`#8e8e93`, `#c6c6cd` 탭 비활성 색, `#d5dbd7` 마감 배지, `#e3eae5` 진행바 트랙, `#f5fbf6` 버튼 배경 등)는 [[project_notice_screens]]·[[project_community_screens]] 때 확정된 방침대로 인라인 임의값으로 처리했다. `tailwind.config.js`는 건드리지 않았다.

임의값 스페이싱 사용 전, NativeWind가 기존 spacing 토큰 스케일(`0,4,8,10,12,16,20,24,32`)에 없는 숫자(`h-40`, `gap-13`, `p-18` 등)를 실제로 어떻게 처리하는지 확실치 않아 개발 서버를 띄워 생성된 CSS를 직접 확인했다 — `h-40`이 `height:40px`로, `gap-13`이 `gap:13px`로 정상 변환되는 것을 확인했다(스케일에 없는 숫자도 "숫자=px"로 그대로 해석). 기존 화면들(공지사항/커뮤니티)도 같은 방식을 이미 써 왔으므로 별도 조치는 필요 없었다.
