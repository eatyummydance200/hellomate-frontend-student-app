# 공지사항 정적 화면 4종 구현 보고서

## 배경

Phase 4(정적 화면 퍼블리싱)의 첫 배치로, Figma `hellomate-workspace` 파일의 공지사항 화면 그룹(노드 `51:219`) 4종을 API 연동 없이 더미 데이터로 하드코딩 구현했다. 반복 요소(카드, 데이터 배열 등)는 이번 단계 방침에 따라 별도 컴포넌트/파일로 뽑지 않고 각 화면 파일 안에 그대로 중복 작성했다.

대상 화면 4종과 Figma 노드:

| 화면 | Figma 노드 | 구현 파일 |
| --- | --- | --- |
| 공지사항 홈 | 24:239 | `app/(tabs)/index.tsx` |
| 전체 공지사항 | 24:334 | `app/notice/all.tsx` |
| 공지사항 상세 | 24:394 | `app/notice/[id].tsx` |
| 담당자 문의 | 24:428 | `app/notice/contact.tsx` |

## 라우팅 구조

`app/notice/_layout.tsx`를 새로 만들어 중첩 Stack을 구성했다.

- 4개 화면 모두 Figma 시안대로 자체 헤더(뒤로가기 화살표 또는 X 닫기)를 직접 그리기 때문에, 네이티브 Stack 헤더는 `headerShown: false`로 전부 숨김
- `contact` 화면은 "담당자에게 질문하기" 버튼으로 진입하는 흐름이고 Figma 헤더에 뒤로가기 화살표 대신 X(닫기) 아이콘이 있어, `presentation: 'modal'`로 등록
- 상세 화면(`[id].tsx`)은 동적 라우트지만 현재는 `id` 파라미터를 실제로 사용하지 않고 Figma 시안 내용을 고정 출력한다. 실제 데이터 조회 연동은 Phase 5 몫으로 남겨둠

## 아키텍처 변경: 네이티브 탭바 숨김

Figma 공지사항 홈 화면은 하단에 둥근 pill 모양의 커스텀 `BottomNav` 컴포넌트가 화면 콘텐츠의 일부로 포함되어 있다. 기존 `app/(tabs)/_layout.tsx`는 Expo Router의 기본 `<Tabs>` 네이티브 탭바를 그대로 쓰고 있었는데, 이 상태로 커스텀 `BottomNav`를 화면에 얹으면 하단 네비게이션이 두 줄로 겹쳐 보인다.

이를 막기 위해 `(tabs)/_layout.tsx`에 `tabBarStyle: { display: 'none' }`을 추가해 네이티브 탭바를 전역으로 숨겼다. 이 변경은 5개 탭 전체에 적용되므로, 아직 텍스트만 있는 placeholder인 커뮤니티/클럽/정보/마이페이지 화면은 해당 화면들이 각자 Header/BottomNav를 갖추기 전까지 하단 네비게이션이 보이지 않는 과도기 상태가 된다. 다음 화면 배치에서 각 탭에 실제 Header/BottomNav를 붙이면 자연히 해소된다.

## 화면별 구현 내용

### 1. 공지사항 홈 (`app/(tabs)/index.tsx`)

- 기존 공통 컴포넌트 `Header`, `BottomNav`를 그대로 재사용
- 히어로 타이틀 + "중요" 배지가 달린 그린 배너 카드(건강보험 안내) + 진행 도트 4개 + 최근 공지 리스트(4건, 읽음/안읽음 상태 구분 — 안읽음 항목은 원 도트 표시, 읽은 항목은 `opacity-50`으로 흐리게 처리)
- 리스트 항목 클릭 시 `router.push({ pathname: '/notice/[id]', params: { id } })`로 상세 화면 이동
- "전체보기" 클릭 시 `/notice/all`로 이동
- 벨 아이콘 클릭 시 기존 `/notifications` 화면으로 이동

### 2. 전체 공지사항 (`app/notice/all.tsx`)

- 자체 뒤로가기 헤더 + 검색창(현재는 UI만, 검색 로직 없음) + 부서 필터 칩(전체/국제교류처/학생처/장학처)
- 필터 칩은 장식용이 아니라 실제로 눌렀을 때 목록을 해당 부서로 걸러내도록 `useState` + `filter()`로 구현 — Phase 4가 "API 연동 없음"이지 "클릭해도 아무 반응 없음"을 뜻하진 않는다고 판단해 최소한의 로컬 상태만 추가
- 더미 공지 4건, 각 카드는 부서별 파스텔 배지(라벤더/피치/옐로우) + 2줄 요약 + 날짜

### 3. 공지사항 상세 (`app/notice/[id].tsx`)

- 자체 뒤로가기 헤더 + 제목/부서 배지/날짜 카드 + 본문 카드(불릿 리스트) + 첨부파일 카드(파일명/용량 + 다운로드 버튼, 다운로드는 UI만) + 하단 고정 "담당자에게 질문하기" CTA 버튼
- CTA 클릭 시 `/notice/contact`(모달)로 이동

### 4. 담당자 문의 (`app/notice/contact.tsx`)

- 헤더에 담당자 아바타를 새로 만들지 않고 기존 공통 컴포넌트 `Avatar`(`size="sm"`)를 재사용
- 문의 중인 공지 배너 + 날짜 구분선 + 채팅 버블 3건(직원 2, 나 1, 안읽음 카운트 1건 포함) + 하단 메시지 입력 바(UI만, 전송 로직 없음)
- 헤더 X 버튼과 배경 탭 모두 `router.back()`으로 닫힘

## 토큰 결정

이번 4개 화면에서 `tailwind.config.js` 기존 토큰과 정확히 일치하지 않는 값(글자 크기 24/19/15/18/13px, 부서 태그 파스텔 배경 3종, 검색창 placeholder gray `#8b8b8b`, 상세 헤더 타이틀 gray `#3d3d3d`, 진행바 강조색 `#575c83` 등)이 다수 발견되어 사용자에게 처리 방식을 확인했다.

**결정:** `tailwind.config.js`는 건드리지 않고, 각 화면 파일 안에서 `text-[19px]`, `bg-[#575c83]` 같은 인라인 임의값(arbitrary value) 클래스로 Figma 값을 그대로 반영. Phase 4는 하드코딩 단계이므로 토큰 확장은 이후 컴포넌트화 시점으로 미룸. `border-border-strong/30`, `bg-primary-light/20`처럼 기존 토큰에 투명도만 얹으면 Figma 값과 정확히 일치하는 경우는 토큰을 그대로 활용.

박스 섀도우는 기존 `Card` 컴포넌트 작업 때와 동일하게 정확한 다중 레이어 그림자값을 쫓지 않고 Tailwind 기본 `shadow-sm`/`shadow-lg`로 근사 처리했다(선례와 일관성 유지).
